Virtual Try-On with FASHN VTON: Integrating Generative AI in Fashion

Surya Bahadur Shahi

Virtual try-on (VTON) is one of the most visually impressive applications of generative AI — but getting it to work reliably on real users with varying poses, lighting, and body types is a different challenge entirely. Here's how I built StyleAI using FASHN VTON, a state-of-the-art diffusion-based virtual try-on model.

The Virtual Try-On Problem

Traditional VTON approaches (CP-VTON, ACGPN, VITON-HD) use GANs with warping modules. They struggle with:

  • Pose mismatch: Person's pose ≠ garment's canonical pose
  • Occlusion handling: Arms crossing torso, hair over shoulders
  • Texture preservation: Patterns, logos, text on garments get distorted
  • Identity preservation: Person's face/body shape changes subtly

FASHN (FAshion SHape aNd texture) takes a different approach: a single diffusion model conditioned on both person and garment images, with explicit pose and shape guidance. No separate warping module — the diffusion model learns to "imagine" the garment on the person.

FASHN Architecture Overview

FASHN uses a latent diffusion model (based on Stable Diffusion architecture) with three conditioning inputs:

  1. Person Image: Full-body photo (512×384 or 768×576)
  2. Garment Image: Clean product photo on white background
  3. Pose/Keypoints: OpenPose/DW-Pose keypoints from person image
# FASHN inference pipeline (simplified)
from diffusers import StableDiffusionControlNetPipeline
from controlnet_aux import OpenposeDetector
import torch
from PIL import Image

# Load models
pipe = StableDiffusionControlNetPipeline.from_pretrained(
    "FASHN-Research/FASHN-VTON",
    torch_dtype=torch.float16,
    variant="fp16"
).to("cuda")

pose_detector = OpenposeDetector.from_pretrained("lllyasviel/ControlNet")

def virtual_tryon(person_img: Image, garment_img: Image, num_steps=30, guidance=2.5):
    # 1. Extract pose from person
    pose_img = pose_detector(person_img, detect_resolution=512, image_resolution=512)

    # 2. Preprocess garment (remove background, resize)
    garment_processed = preprocess_garment(garment_img)

    # 3. Run diffusion
    result = pipe(
        prompt="high quality, photorealistic, fashion photography",
        negative_prompt="blurry, low quality, distorted, deformed, ugly, bad anatomy",
        image=person_img,
        control_image=[pose_img, garment_processed],  # Dual ControlNet
        num_inference_steps=num_steps,
        guidance_scale=guidance,
        controlnet_conditioning_scale=[1.0, 1.0],
        generator=torch.Generator("cuda").manual_seed(42)
    ).images[0]

    return result

Production Challenges & Solutions

1. Background Removal for Garments

FASHN expects clean garment images on transparent/white backgrounds. User uploads rarely meet this. 

# Garment preprocessing pipeline
from rembg import remove
from PIL import Image
import numpy as np

def preprocess_garment(garment_img: Image, target_size=(512, 512)) -> Image:
    # 1. Remove background
    garment_nobg = remove(garment_img)  # Returns RGBA

    # 2. Create white background version for ControlNet
    white_bg = Image.new("RGB", garment_nobg.size, (255, 255, 255))
    white_bg.paste(garment_nobg, mask=garment_nobg.split()[3])  # Alpha as mask

    # 3. Crop to garment bounds (remove excess whitespace)
    bbox = garment_nobg.getbbox()
    if bbox:
        white_bg = white_bg.crop(bbox)

    # 4. Resize maintaining aspect, pad to square
    white_bg = resize_and_pad(white_bg, target_size)

    return white_bg

def resize_and_pad(img: Image, target_size: tuple) -> Image:
    # Resize keeping aspect ratio
    img.thumbnail(target_size, Image.Resampling.LANCZOS)

    # Pad to target size
    new_img = Image.new("RGB", target_size, (255, 255, 255))
    paste_x = (target_size[0] - img.width) // 2
    paste_y = (target_size[1] - img.height) // 2
    new_img.paste(img, (paste_x, paste_y))
    return new_img

2. Pose Estimation Robustness

OpenPose/DW-Pose fails on: unusual poses, occlusions, low resolution, multiple people. 

# Robust pose extraction with fallback
from controlnet_aux import DWposeDetector

pose_detector = DWposeDetector.from_pretrained("yzd-v/DWPose")

def extract_pose_robust(person_img: Image) -> Image:
    # Try DWPose first (more accurate)
    try:
        pose_img = pose_detector(
            person_img,
            detect_resolution=512,
            image_resolution=512,
            output_type="pil"
        )
        # Validate: check if keypoints detected
        if is_valid_pose(pose_img):
            return pose_img
    except Exception as e:
        logger.warning(f"DWPose failed: {e}")

    # Fallback to OpenPose
    try:
        pose_img = openpose_detector(person_img, detect_resolution=512, image_resolution=512)
        return pose_img
    except Exception as e:
        logger.error(f"OpenPose also failed: {e}")
        # Return blank pose (will generate generic result)
        return Image.new("RGB", (512, 512), (0, 0, 0))

def is_valid_pose(pose_img: Image, min_keypoints=10) -> bool:
    # Simple heuristic: count non-black pixels in pose image
    arr = np.array(pose_img)
    non_black = np.sum(np.any(arr > 10, axis=2))
    return non_black > min_keypoints * 50  # Rough threshold

3. Inference Optimization for Web

Diffusion models are slow. 30 steps on A10G takes ~3-4 seconds. For web UX, we need <2s perceived latency.

Optimization Latency Quality Impact Implementation
FP16 (half precision) ~3.2s Negligible torch.float16
xFormers memory efficient attention ~2.8s None pip install xformers
Reduced steps (30 → 20) ~2.1s Slight noise num_inference_steps=20
LCM-LoRA (4-8 steps) ~0.8s Moderate Load LCM LoRA weights
TensorRT / ONNX Runtime ~1.5s None Export to ONNX + TensorRT

For StyleAI, I used 20 steps + xFormers + FP16 on RunPod A10G — ~2.1s end-to-end. Good enough for "generating..." UX with progress indicator.

4. API Architecture: Async Queue

GPU inference blocks the event loop. Use a job queue with worker processes. 

# FastAPI + Celery + Redis for async inference
# api/main.py
from fastapi import FastAPI, UploadFile, File, Form, BackgroundTasks
from fastapi.responses import JSONResponse
import uuid

app = FastAPI()

@app.post("/api/vton")
async def virtual_tryon(
    person: UploadFile = File(...),
    garment: UploadFile = File(...),
    steps: int = Form(20),
    guidance: float = Form(2.5)
):
    job_id = str(uuid.uuid4())

    # Save uploads
    person_path = f"/tmp/{job_id}_person.jpg"
    garment_path = f"/tmp/{job_id}_garment.jpg"

    with open(person_path, "wb") as f:
        f.write(await person.read())
    with open(garment_path, "wb") as f:
        f.write(await garment.read())

    # Queue job
    from workers.vton_worker import process_vton
    process_vton.delay(job_id, person_path, garment_path, steps, guidance)

    return JSONResponse({"job_id": job_id, "status": "queued"})

@app.get("/api/vton/{job_id}")
async def get_vton_result(job_id: str):
    # Check Redis for result
    result = redis.get(f"vton:result:{job_id}")
    if result:
        return JSONResponse({"status": "completed", "result_url": result})

    status = redis.get(f"vton:status:{job_id}")
    return JSONResponse({"status": status or "pending"})


# workers/vton_worker.py
from celery import Celery
import torch
from PIL import Image

celery = Celery('vton', broker='redis://redis:6379/0')

@celery.task(bind=True, max_retries=3)
def process_vton(self, job_id, person_path, garment_path, steps, guidance):
    try:
        redis.set(f"vton:status:{job_id}", "processing")

        # Load models (cached globally in worker)
        from model_loader import get_pipeline
        pipe = get_pipeline()

        # Run inference
        person_img = Image.open(person_path).convert("RGB")
        garment_img = Image.open(garment_path).convert("RGB")

        result = run_inference(pipe, person_img, garment_img, steps, guidance)

        # Save result
        result_path = f"/results/{job_id}.jpg"
        result.save(result_path, quality=90)

        # Upload to S3/CDN
        result_url = upload_to_cdn(result_path, f"vton/{job_id}.jpg")

        redis.set(f"vton:result:{job_id}", result_url)
        redis.set(f"vton:status:{job_id}", "completed")

    except Exception as e:
        redis.set(f"vton:status:{job_id}", f"failed: {str(e)}")
        raise self.retry(exc=e, countdown=60)

Quality Control & Safety

Generative models can produce artifacts. Implement validation:

  • Face preservation: Compare face embeddings (ArcFace) before/after — reject if similarity < 0.85
  • Garment recognition: CLIP similarity between input garment and generated region — reject if < 0.7
  • NSFW filter: Run safety checker on output
  • Anatomical validity: Pose detector on output — keypoints should be reasonable
# Quality validation pipeline
import clip
import torch
from insightface.app import FaceAnalysis

face_app = FaceAnalysis(name='buffalo_l')
face_app.prepare(ctx_id=0)

def validate_result(original_person, generated, garment_img):
    results = {}

    # 1. Face preservation
    orig_faces = face_app.get(np.array(original_person))
    gen_faces = face_app.get(np.array(generated))
    if orig_faces and gen_faces:
        orig_emb = orig_faces[0].normed_embedding
        gen_emb = gen_faces[0].normed_embedding
        results['face_similarity'] = float(np.dot(orig_emb, gen_emb))

    # 2. Garment preservation (CLIP)
    device = "cuda"
    model, preprocess = clip.load("ViT-B/32", device=device)

    garment_tensor = preprocess(garment_img).unsqueeze(0).to(device)
    # Crop generated torso region (approximate)
    gen_crop = generated.crop((180, 200, 380, 450))
    gen_tensor = preprocess(gen_crop).unsqueeze(0).to(device)

    with torch.no_grad():
        garment_feat = model.encode_image(garment_tensor)
        gen_feat = model.encode_image(gen_tensor)
        results['garment_similarity'] = float(
            torch.cosine_similarity(garment_feat, gen_feat).item()
        )

    # 3. NSFW check
    from diffusers.pipelines.stable_diffusion.safety_checker import StableDiffusionSafetyChecker
    safety = StableDiffusionSafetyChecker.from_pretrained("CompVis/stable-diffusion-safety-checker")
    _, has_nsfw = safety(images=[generated])
    results['nsfw'] = bool(has_nsfw[0])

    # Pass/fail
    passed = (
        results.get('face_similarity', 0) > 0.85 and
        results.get('garment_similarity', 0) > 0.7 and
        not results.get('nsfw', True)
    )

    return {**results, 'passed': passed}

Cost Optimization

GPU time is expensive. Strategies that cut StyleAI's inference cost by ~60%:

Strategy Savings Trade-off
Spot instances (RunPod/AWS) 60-70% Preemption handling needed
Batch inference (4+ images) 3-4x throughput Higher latency per request
Model caching (keep loaded) ~10s cold start Memory pressure
LCM-LoRA for previews 4x faster Lower quality preview
CDN caching results Repeat requests free Storage cost

Conclusion

Virtual try-on is a perfect showcase for diffusion models — visually impressive, clear user value, and technically challenging enough to be interesting. FASHN VTON's diffusion-based approach eliminates the error-prone warping stage of GAN methods, but requires careful engineering around preprocessing, inference optimization, and quality control.
